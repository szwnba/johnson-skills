# ZCode 任务完成 → 飞书群推送 · 配置说明（Windows / Linux 通用版）

> 用途：换电脑后，把本文件交给 agent，它照做即可完成重配置。
> 功能：ZCode 每次回复结束（`Stop` 事件），自动往飞书群推一条「ZCode 任务完成」。
> 适用：Windows 10+、Linux（macOS 同 Linux，未实测）。
> 实测记录：Windows 原方案已验证；Linux 于 2026-11-07 全流程验证通过（含端到端）。

## 1. 前提

- 飞书群自定义机器人已创建（群设置 → 群机器人 → 自定义机器人），**签名校验必须保持关闭**
- 系统有可用 curl：Windows 10+ 自带 `curl.exe`；Linux / macOS 自带 `curl`

**Webhook（凭证，勿公开分享；泄露后在飞书机器人设置里重置）：**

```
https://open.feishu.cn/open-apis/bot/v2/hook/bb03bd21-3dfa-49c4-a8af-21f44b30b5f9
```

## 2. 平台差异速查（只有这几处要"区别对待"，其余全部一样）

| 项目 | Windows | Linux / macOS |
|---|---|---|
| 配置文件路径 | `C:\Users\<用户名>\.zcode\cli\config.json` | `~/.zcode/cli/config.json` |
| `command` | `curl.exe` | `curl` |
| 丢弃输出 | `-o NUL` | `-o /dev/null` |
| 中文编码风险 | 有（GBK），必须用 `\u` 转义 | 无（UTF-8），但仍保留转义（见 4.4） |
| JSON 校验 | `python -I` | `python3 -I` |

**两平台完全一致的部分**：`"enabled": true`、事件名 `Stop`、`type: "process"`、`-d` 载荷内容、`timeoutMs`、改完必须重启 ZCode。

## 3. 要合并进 config.json 的配置块

注意：文件里可能已有 `plugins` 等其他内容，**把 `hooks` 段合并进去，不要整体覆盖**。两个平台的配置块只有 `command` 和 `-o` 目标两处不同。

**Windows 版：**

```json
{
  "hooks": {
    "enabled": true,
    "events": {
      "Stop": [
        {
          "hooks": [
            {
              "type": "process",
              "command": "curl.exe",
              "args": [
                "-s", "-o", "NUL", "-X", "POST",
                "https://open.feishu.cn/open-apis/bot/v2/hook/bb03bd21-3dfa-49c4-a8af-21f44b30b5f9",
                "-H", "Content-Type: application/json",
                "-d", "{\"msg_type\":\"text\",\"content\":{\"text\":\"ZCode \\u4efb\\u52a1\\u5b8c\\u6210\"}}"
              ],
              "timeoutMs": 10000
            }
          ]
        }
      ]
    }
  }
}
```

**Linux / macOS 版：**

```json
{
  "hooks": {
    "enabled": true,
    "events": {
      "Stop": [
        {
          "hooks": [
            {
              "type": "process",
              "command": "curl",
              "args": [
                "-s", "-o", "/dev/null", "-X", "POST",
                "https://open.feishu.cn/open-apis/bot/v2/hook/bb03bd21-3dfa-49c4-a8af-21f44b30b5f9",
                "-H", "Content-Type: application/json",
                "-d", "{\"msg_type\":\"text\",\"content\":{\"text\":\"ZCode \\u4efb\\u52a1\\u5b8c\\u6210\"}}"
              ],
              "timeoutMs": 10000
            }
          ]
        }
      ]
    }
  }
}
```

## 4. ⚠️ 关键点（全部实测踩过的坑，勿"优化"）

1. **`"enabled": true` 必须写**（两平台）。配置文件里的 hook 默认是禁用的，不写这行就永远不会触发。
2. **事件名必须是 `Stop`**（两平台）。ZCode 仅支持 7 个事件（SessionStart / UserPromptSubmit / PreToolUse / PermissionRequest / PostToolUse / PostToolUseFailure / Stop），没有 Notification。
3. **`type: "process"` 直接调 curl、不经 shell**（两平台）。Windows 上避开引号和编码问题，Linux 上避开引号问题，都建议用。
4. **`-d` 里的 `\\u4efb\\u52a1\\u5b8c\\u6210` 是故意的，别改成直接写中文！**
   - 原理（两平台相同）：config.json 里的 `\\u` 解析后是"字面反斜杠 + u"，curl 原样发出 `\u4efb`，飞书解析 JSON 时还原成「任」。到达 curl 的参数应该是这个**纯 ASCII** 字符串：`{"msg_type":"text","content":{"text":"ZCode \u4efb\u52a1\u5b8c\u6210"}}`
   - Windows：必须转义。中文系统的 GBK 编码会把中文字节搞乱（实测踩坑：Server酱 收到 GBK 字节直接报数据库错误）。
   - Linux：UTF-8 下直接写中文理论上也能通，但**同样保留转义**——纯 ASCII 载荷与终端 / locale 无关，且两平台配置块可保持一致（Linux 实测：转义写法飞书返回 `code:0`，消息正确渲染成「任务完成」）。
   - 只写单个 `\u`（单反斜杠）会被 config.json 的 JSON 解析还原成真实汉字，Windows 上同样有 GBK 风险，别这么写。
5. **丢弃输出的参数必须保留**（Windows `-o NUL` / Linux `-o /dev/null`）。hook 的 stdout 会被按严格 JSON schema 校验，把 curl 输出的服务端响应漏出去会导致 hook 被记为失败。
6. **改完配置必须重启 ZCode** 才生效（hook 配置在会话启动时加载，两平台相同）。

## 5. 验证步骤

**① Webhook 手动测试**（Linux / macOS 直接执行；Windows 在 Git Bash 里执行，CMD 不认单引号。返回 `"code":0` 且群里出现消息即通）：

```bash
curl -s -X POST "https://open.feishu.cn/open-apis/bot/v2/hook/bb03bd21-3dfa-49c4-a8af-21f44b30b5f9" \
  -H "Content-Type: application/json" \
  -d '{"msg_type":"text","content":{"text":"ZCode test"}}'
```

**② config.json 语法校验**（打印 OK 即合法；路径按平台替换）：

```bash
# Linux / macOS
python3 -I -c "import json; json.load(open('$HOME/.zcode/cli/config.json', encoding='utf-8')); print('OK')"

# Windows
python -I -c "import json; json.load(open(r'C:\Users\<用户名>\.zcode\cli\config.json', encoding='utf-8')); print('OK')"
```

**③ 载荷模拟验证**（可选但推荐，Linux 实测有效）：从写好的 config 里取出 hook 实际会执行的参数跑一次，确认 `-d` 是纯 ASCII、飞书接受转义载荷（群里会出现一条真的「ZCode 任务完成」）。Linux / macOS 用 `python3`，Windows Git Bash 用 `python`，路径按平台替换：

```bash
python3 -I -c "
import json, subprocess
cfg = json.load(open('$HOME/.zcode/cli/config.json', encoding='utf-8'))
h = cfg['hooks']['events']['Stop'][0]['hooks'][0]
args = [h['command']] + h['args']
d = args[args.index('-d')+1]
assert all(ord(c) < 128 for c in d), 'non-ASCII found in -d'
args[args.index('-o')+1] = '-'   # 仅验证时改为回收响应
r = subprocess.run(args, capture_output=True, text=True)
print(r.stdout)
"
```

**④ 端到端验证**：重启 ZCode 后对 agent 说「试一下」，这条回复结束时看飞书群是否弹出「ZCode 任务完成」。

## 6. 换电脑后的重配置流程（给 agent 的操作清单）

1. 读本文档。
2. 判断平台（Linux/macOS 还是 Windows），按第 2 节速查表确定差异项。
3. 定位目标机的 config.json（Linux/macOS：`~/.zcode/cli/config.json`；Windows：`C:\Users\<用户名>\.zcode\cli\config.json`），不存在则创建空 JSON 再合并。
4. 把第 3 节**对应平台**的 `hooks` 块合并进去，保留原有内容。
5. 用第 5 节 ② 校验 JSON 合法；建议再做 ③ 载荷模拟验证。
6. 用第 5 节 ① 手动测 Webhook；若失败（webhook 可能已被重置），让用户去飞书群机器人设置里重取 URL，更新配置里的 URL。
7. 提醒用户重启 ZCode，再按第 5 节 ④ 做端到端确认。
8. 不通过时，查 ZCode 日志中的 hook 执行记录（是否 fired / 超时 / 失败）定位。
